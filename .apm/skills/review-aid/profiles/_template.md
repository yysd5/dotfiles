# <プロジェクト名> プロファイル

このファイルはひな形。社内の情報を含むので、実際のプロファイルは Skill 本体には置かず、
対象リポジトリの `.review-aid/profile.md`（`.git/info/exclude` などで Git 管理外にする）か `~/.config/review-aid/profiles/<name>.md` に置く。
項目は、分かるものだけ書けばよい。書いていない項目は、Skill が汎用の既定値で進めるか、ユーザーに聞く。

## レビュー観点

- 使うレビュー観点の Skill（例 `<repo>-code-reviewer`）。観点番号を指摘の `persp` に使う
- 観点に「ドキュメントの更新」がある場合、AI から見られないドキュメントの一覧

## 比較ブランチ

- 既定の比較先（例 `develop`）

## 仕様書・関連ドキュメント

- 置き場所と取得手段（使うツール、スペース、検索のコツ）
- チケットの URL の形

## 実データの確認

- DB などを参照できるツールと、参照してよい範囲
- 参照できないデータストア（ファイル型 DB、KVS など）の形を知る手がかり（定義ファイル、設定ファイル、テストのフィクスチャ）

## 実行モデル

- データのロード（起動時、定期ロード、キャッシュ）の仕組みと、主なクラス
- リクエスト処理の入口から出力までの主な流れ
- 設定値の置き場所

## テストの実行

- 特定のテストだけを実行するコマンド
- 事前に必要なビルド、オフラインで失敗するときの対処
- CI で実行されないテスト

## 読まなくてよい生成物

- 生成コードのパターン（例 `*Proto.java`、`*_pb2.py`）

## 出力先

- 手元に出す HTML の既定（省略時は `~/review-aid/<リポジトリ名>/<ブランチ名>.html`）

## 実例データ

- 過去に作ったデータ JSON の場所（新しく作るときの参考）
