# 図の描き方（inline SVG）

図は、読み手が文章を読む前に全体の形をつかむためにある。
図の中の要素は、本文やコードの名前（クラス名、テーブル名、設定キー）と一致させ、図から本文・コードへたどれるようにする。

## 目次

- 共通のルール
- 両テーマ対応の書き方
- 4つの型
- 図に添えるもの

## 共通のルール

- `<figure class="dg">` で囲み、`<figcaption>` に「図n 何を表す図か」を書く
- `<svg>` には `viewBox` と、原寸の上限として `width` を付ける。`height` は付けない（縦横比が保たれる）
- `role="img"` と `aria-label`（図の要旨を1文で）を付ける
- 幅は 720 以下を目安にする。スマホ幅では縮小されるので、文字が小さくなりすぎないよう要素を詰め込みすぎない
- 1つの図に載せる箱は10個程度まで。超えるなら図を分ける
- 色は意味に使う（例: 今回の変更対象、外部システム、問題のある箇所）。意味の無い色分けはしない。使ったら凡例を添える

## 両テーマ対応の書き方

色を直接書かず、テンプレートの CSS クラスを使う。クラスはトークン経由で色が決まるので、ライト／ダークの両方で読める。

| クラス | 用途 |
|---|---|
| `text` | 既定の文字色（指定不要） |
| `text.mute` | 補足の小さい文字（矢印のラベルなど） |
| `rect.box` | 既定の箱 |
| `rect.box.alt` | 背景に近い箱（外枠、グループ） |
| `rect.box.a` | 青系。注目する要素 |
| `rect.box.b` | 緑系。正常・完了・出力 |
| `rect.box.c` | 黄系。注意・設定 |
| `rect.box.d` | 赤系。問題・ずれ |
| `path.edge` | 線・矢印 |
| `path.edge.dash` | 点線。任意・非同期・参照のみ |

矢印の先は `<marker>` で定義する。`id` は資料内で一意にする（図ごとに `ah1`、`ah2` など）。

```html
<defs><marker id="ah1" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7"
  orient="auto-start-reverse"><path class="arrow" d="M0,0 L10,5 L0,10 z"/></marker></defs>
<path class="edge" d="M140,55 H193" marker-end="url(#ah1)"/>
```

`fill="#..."` や `stroke="black"` のような直書きをすると、片方のテーマで見えなくなる。新しい色が要るときは、`:root` と2か所のダーク定義の3か所にトークンを足す。

## 4つの型

### 流れ（処理・データ）

- 左から右、または上から下の一方向に並べる。逆流する矢印は点線にする
- 矢印に、渡すもの（データ名、メソッド名）を `text.mute` で書く
- システムの境界は `rect.box.alt` の大きな枠で囲み、枠の左上に名前を書く

### 関係（テーブルの参照関係など）

- 箱の中に、名前（太字）と、関係に効く列だけを書く。全列は載せない
- 線の端に多重度（1、N）を書く
- 実データの件数が分かっていれば箱の下に `text.mute` で添える（「約12万行、2026-10-15 時点」）

### シーケンス（時系列のやり取り）

- 参加者を横に並べ、縦の点線（ライフライン）を引く。時間は上から下
- メッセージは横向きの矢印。応答は点線
- 順番の番号（1, 2, 3…）を矢印のラベルの先頭に付け、本文の説明と番号で対応させる

### 入れ子（包含・優先順位）

- 外側の箱の中に内側の箱を置く。優先順位なら、強いものを内側（または上）にする
- 各層に「どこで設定するか」を `text.mute` で添える
- 例: 設定の優先順位（デフォルト < 設定ファイル < 環境変数 < 引数）、ラッパーと中身

## 図に添えるもの

- `figcaption` の後に、図の読み方を1〜2文で書く。図だけで終わらせない
- 図の要素に対応するコードの場所や出典を、図の直後の文に `[n]` で付ける
- 推測で描いた部分があるなら、その箱を `rect.box.c` にするか点線にして、`推測` ラベルを添える
